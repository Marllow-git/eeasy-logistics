# apps/web

- Next.js 16 App Router. Route groups `src/app/(auth)`, `(merchant)`, `(recipient)/track/[token]`, each its own root layout: `import '@eeasy-logistics/ui/styles.css'`, `export const generateMetadata = rootMetadata`, `<RootHtml namespaces={[...]}>` around `<AppShell brand navigation topBar={<LocaleSwitch />}>` (merchant has navigation; auth and recipient pass `navigation={[]}`, top bar only) → `mem:ui/core`. No platform route: the console is `apps/admin` (ADR-0038, WEB-19) → `mem:admin/core`; `GET /platform` is 404.
- Locale (WEB-1): `ar` default, RTL; next-intl non-routing via `createNextIntlPlugin('./src/i18n/request.ts')`, which re-exports `@eeasy-logistics/ui/shell/request-config` (`el_locale` cookie, a missing message throws). Pages use `getTranslations` (server) / `useTranslations` (client), typed from the `ar` catalogue. Tailwind 4 via `postcss.config.mjs` (`@tailwindcss/postcss`); logical utilities only (lint `eeasy/no-physical-direction-utilities`). `next.config.ts` sends `X-Content-Type-Options: nosniff`; CSP and frame headers are WEB-2's.
- Config: only `NEXT_PUBLIC_*` via `@eeasy-logistics/config/web` (`publicConfig()`); dependency-cruiser forbids any other config import; server-side vars come with the order that adds server fetches.
- API access only via `@eeasy-logistics/contracts` (`/staff`, `/recipient`, `/http`, `/unions`; rule `web-contracts-surfaces`). Generated calls take `{ fetcher: createFetcher({ baseUrl, locale, headers }) }` per call; `baseUrl` is the origin (paths carry `/v1/<surface>`). `next build` typechecks, so contracts must be built first (Turbo `^build`; Dockerfile builds `@eeasy-logistics/web...`).
- `typecheck` runs `next typegen` first (typed routes). Census (WEB-1): `tests/census.config.ts` (projects `ar` 1440 px, `ar-390`, `en` 1440 px; locale from `metadata.locale` → `el_locale` cookie; base URL fixed `http://127.0.0.1:3001`; `testMatch` lists every spec), helpers `tests/census/helpers.ts` (`test` fixture, `expectLocale`, `expectNoArabicIndicDigits`, `expectNoRawKeys`, `expectNoHorizontalOverflow` at 390 px, `expectAxeClean` serious/critical WCAG 2.2, `expectSecurityHeaders` nosniff, `recordTraffic` + `expectNoSessionCookies` on recipient pages), spec `tests/census-shell.spec.ts`; baselines `tests/census/__screenshots__/<project>/<name>-<platform>.png` (darwin locally, linux from CI: a missing baseline fails and its `-actual.png` lands in the `web-build-census` artifact). Script `test:census`; CI lane `web-build-census` runs it against the standalone server.
- First-load budget (WEB-1 plan 2.10): `scripts/check-budget.ts` (`check:budget`, also run by `apps/admin`) after `next build`. Next 16 + Turbopack writes no `app-build-manifest.json`: the script reads `.next/diagnostics/route-bundle-stats.json` (route → first-load chunks), `app-path-routes-manifest.json` (route → group → class) and `build-manifest.json` `rootMainFiles` (framework floor, about 128 KB gzip), gzips chunks at level 9. Measure (lead ruling, roadmap A-19, web §10.2): route JS above the floor per group (recipient 90 KB; merchant, platform, auth 180 KB) and the floor itself capped at 135 KB; both numbers printed per route. An unclassified route group fails the script. Pure `checkBudget()` tested by `scripts/check-budget.test.ts` (`node --test`, fixture `scripts/fixtures/route-bundle-stats.json`; script `test:scripts`, part of `test`).
- Architecture rule `web-no-admin-code-or-catalogue`: nothing here imports `apps/admin` (its `platform` catalogue included).
