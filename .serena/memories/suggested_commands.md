# Commands

## Whole repo (from root)
- `pnpm install` (pnpm 10 runs no install scripts except those in `pnpm-workspace.yaml`).
- Lockfile trap (2026-11-01): main's `pnpm-lock.yaml` holds versions younger than `minimumReleaseAge` and a `trustPolicy` downgrade, so any re-resolving install fails. After a `package.json` change: `pnpm install --lockfile-only --config.minimum-release-age=0 --config.trust-policy=off`, check the lockfile diff is additions only and each new version is older than three days (`npm view <pkg> time`), then `pnpm install --frozen-lockfile`. With the gates off pnpm takes the newest match for any NEW transitive dependency, which may be days old (CHORE-1: `http2-wrapper@2.2.2` under `@swc/cli`); pin such a version back to the newest mature one by hand in the lockfile (same deps, its `dist.integrity`), then the frozen install verifies it. Re-resolving with the gates on and targeted excludes instead re-resolves main's own too-young locks (rolldown, @babel) and churns the lockfile.
- `pnpm audit --audit-level moderate` — the CI `pnpm-audit` job (`.github/workflows/audit.yml`, every PR and weekly on main). Accepted advisories live in `pnpm-workspace.yaml` `auditConfig.ignoreGhsas`, each with a reason; add one only after checking it never reaches an image or bundle.
- `pnpm turbo run typecheck lint test build` — the full local gate.
- `pnpm format` / `pnpm format:check`.

## Local stack (no Docker on the owner's machine)
- `tools/native-stack.sh migrate` runs the migration job against the `.env` database (process env wins, so `DATABASE_URL_OWNER=… tools/native-stack.sh migrate` targets a scratch db).
- `tools/native-stack.sh up | status | down | reset` — Homebrew postgresql@17 + postgis, redis, minio, mailpit, whatsapp-stub on the Compose `dev` ports; roles `elx_owner/app/platform/maintenance`, db `elx`. Data under `.local/native-stack`. Mode (dedicated cluster vs existing 5432) fixed at first `up`.
- Compose (`compose.yaml`, profiles `dev|ci|stack-a|stack-b`) only in CI; `tools/stack.sh` for isolated stack pairs there.

## Workflow
- `tools/pr-gate.sh <PR>` before any merge (checks head, CI, plan §8/§9, release note, template). It prints `docs-only: yes|no` from `tools/changed-scope.sh` (the same classifier CI uses to skip build and test lanes on docs-only PRs) and fails a code PR whose required lane did not succeed.
- `gh pr create` from `.github/pull_request_template.md`; branch `feat/<ORDER-ID>-<slug>` with `docs/orders/<ID>/plan.md` as first commit.
- `git worktree list` / `git worktree prune` — executor worktrees live under `.claude/worktrees/`.
- Serena trap (2026-11-01, PLAT-9): the Serena MCP server can be shared by parallel sessions, and another session's `activate_project` silently retargets your symbol edits to its worktree. Re-activate your worktree right before every Serena edit (or edit with file tools) and check `git status` in both worktrees after one.
- `.env.example` is sourced by bash (CI, `native-stack.sh`): quote any value with spaces or `<>` (`MAIL_FROM="Name <a@b>"`); `util.parseEnv` strips the quotes.

## Darwin notes
- The owner's default `node` is 22; the repo needs 24. `brew install node@24` (keg-only, never linked) and prefix commands with `PATH=/opt/homebrew/opt/node@24/bin:$PATH`; the Homebrew `pnpm` shim then runs on 24 (CHORE-1).
- The native stack's `up` refuses when the owner's server already holds `elx` it did not create: run integration through the scratch-database harness, and MinIO from a scratch dir (`minio server <dir> --address 127.0.0.1:9000`, bucket `elx-local` versioned via `mc`) for the `/ready` tests.
- Homebrew paths: `/opt/homebrew/opt/postgresql@17/bin` (override `ELX_NATIVE_PG_BIN`). `brew install gitleaks` required for the pre-commit hook.
- BSD `sed -i ''`; `base64 -d` works; use `grep -E` not `grep -P`.
