# Conventions

## Code
- TypeScript strict everywhere; ESM; explicit `.ts` relative imports inside packages; exact dependency pins.
- Config: declare a setting once in `packages/config` Zod schemas; secrets wrapped in `Secret` (`reveal()`), never logged; new adapter selectors register in `refusals.ts` `adapterSelectors`. Web/driver read only `NEXT_PUBLIC_*` / `EXPO_PUBLIC_*` through `publicConfig()` with literal `process.env.X` reads (bundler inlining) — only `node.ts`, `web.ts`, `driver.ts` are lint-exempt.
- API contexts: `apps/api/src/modules/{kernel,delivery,wms}/`; cross-context imports only from `public/index.ts`. Architecture fixtures: permitted imports under `apps/api/test/architecture/fixture` (cruised by `test:architecture`); rule-breaking ones under `.../violations/`, asserted by `test/architecture-violations.test.ts`; add one of each when adding a rule. Telemetry (PLAT-14): a provider call in an adapter runs inside `withPortSpan({ port, method, provider, accountId, outboxRowId, attempt }, fn)` (kernel `public/index.ts`); a new span attribute key must be added to `spanAttributeAllowlist` or it is dropped at export; a new metric goes in `metricCatalogue` (and its alert in `observability/alerts.yaml`); log through `new Logger(context)` (the JSON logger redacts), never `console`.
- API naming (handbook 04): plural kebab-case paths, `snake_case` JSON, ISO 8601 with offset, money as integer halalas + currency, error `{code,message,details?}` with stable codes, `Idempotency-Key` on retryable writes.
- i18n: keys in `packages/i18n/<locale>/<namespace>.json` (the `platform` namespace only in `apps/admin/messages/<locale>/`, ADR-0038); Arabic catalogue is the reference type (`Messages`; next-intl `AppConfig` in `packages/ui/src/intl.ts`), parity test fails on a key missing in either locale; the `errors` keys equal `ErrorCode`. Dates, numbers, money and phones only through `packages/i18n/src/format.ts`. Logical Tailwind utilities only (lint `eeasy/no-physical-direction-utilities`); directional icons mirror with `rtl:-scale-x-100`. UI components live in `packages/ui/src/components/<name>/<name>.tsx` with a test in both directions.
- API handlers (PLAT-6): import `Public`, `CrossTenant`, `Idempotent`, `ApiException` from `modules/kernel/public`; throw `ApiException('<errors.md code>')`, never an `HttpException` with text; build repositories from `getUnitOfWork()`; retryable writes carry `@Idempotent()` (secret-bearing ones `{ secretResponse: true }`); no `*.dto.ts` or class-validator (A-17); contract input via `@Operation(operationSchemas.<id>)` + `@Input()` (`ContractInput<typeof op>`), return the generated response type, map rows in a `*.presenter.ts`; contracts imports only in `*.controller.ts`/`*.presenter.ts` and only from `/<surface>/schemas` or `/unions`; `@Idempotent()` handlers declare `@HttpCode()` and never carry `@NoUnitOfWork()` (both refused at start by `IdempotentRoutesCheck`, DEL-4 R2); a `CommittedRefusal` commits every earlier write of the transaction, so throw it before the handler's own writes; Express path params use the YAML names (`:account_id`).
- Authorization (PLAT-10): every route on a surface binds a generated operation of that surface as is (a `@Public()` one only a door: `core.auth.anonymous`, `core.auth.self`, `platform.auth.self`; `@CrossTenant()` exactly on `x-cross-tenant` operations) (`@Operation(operationSchemas.<id>)` or a const holding it; no literal, spread or call: ESLint in controllers, `OperationRoutesCheck` at boot); the permission is the entry's `x-permission`, never named by a handler. Handlers on a site-owned resource add `@SiteScoped({ from: 'path'|'query'|'body', name })` and list repositories add `siteFilter(getContext(), table.siteId)`; membership writes call `assertRoleCombination`, approvals `assertSeparation` (kernel public). A bundle change is README §11 + `docs/contracts/roles.yaml` + a re-seed migration (`INSERT … ON CONFLICT (key) DO UPDATE`, as 0008).
- Audit (PLAT-7): inject `AUDIT_SINK`; `record()` for an action in the request's unit of work, `recordCommitted()` only for refusals that must outlive a rollback; action `<module>.<object>.<verb>` past tense (`^[a-z]+\.[a-z_]+\.[a-z_]+$`), never secrets in `before`/`after` (redacted anyway, by key substring). List operations use signed keyset cursors bound to operation, filters and sort (`modules/kernel/audit/cursor.ts`).
- Database: tenant code reads and writes through a `ScopedRepository` subclass in a `*.repository.ts` file inside a unit of work (requests: `getUnitOfWork()`); a new table ships `account_id` (FK + leading index; NULL only for data §2.4 nullable-account tables listed in `nullableAccountTables`), the `tenant_isolation`/`platform_access` policies and, if append-only, `SELECT core_make_append_only('<t>')` in the same migration; hand SQL via `drizzle-kit generate --custom`; never edit an applied migration; new migrations are timestamp-named and never renamed; a parallel merge follows data §11.9 (CHORE-3).
- Dependencies: pnpm refuses versions younger than 3 days (`minimumReleaseAge: 4320`) and fails on a trust downgrade (`trustPolicy: no-downgrade`, checked only for versions under 30 days old: `trustPolicyIgnoreAfter: 43200`); a version needed sooner goes in `minimumReleaseAgeExclude` with a reason. Until 2026-11-04 the lock still holds versions younger than three days (pinned before the rule), so a full re-resolve fails the age gate; executors may relax it in an uncommitted local copy, then check every new version against the registry before committing the lock. A new workspace makes `pnpm install` re-resolve and can trip that rule on a version already in the lock (WEB-19, tslib 2.9.1 until 2026-11-02): copy an identical importer block in `pnpm-lock.yaml` and confirm with `pnpm install --frozen-lockfile` and `--lockfile-only` (no diff). Dependabot (`.github/dependabot.yml`) opens grouped weekly PRs; Expo-pinned packages move only through `npx expo install` in an SDK upgrade, and ESLint 10 / TypeScript 7 majors are held (2026-11-01).
- Tests: unit next to code (`*.test.ts`); integration against real PostgreSQL; behaviour change = red-then-green shown in PR; never weaken a test.
- Test data from contracts (handbook 03): mock the API with the generated `@eeasy-logistics/contracts/<surface>/mocks` (test-only), overriding only asserted fields; API HTTP tests use generated request types and parse responses with the generated response schema; database fixtures stay Drizzle-typed; never hand-write an object literal for a contract shape.

## Repo process
- Branches `docs/…`, `feat/<ORDER-ID>-<slug>`, `fix/…`, `chore/…`; commits `<ID>: <item letter>, <what>`, one per build-list item; co-author trailer supplied by tooling.
- Plan file sections 0–9 (handbook 04): §1 cites file **and heading**; §3 legs ≤5 items; §8.0 progress row committed per item; §8.1 skills/docs with versions+dates; §8.2 interpretations; §8.3 not done; §9 review + adversary table.
- Executors never answer owner questions (roadmap §4 Q-*): build on the default, record interpretation in §8.2.
- Release note `docs/release-notes/YYYY-MM-DD-<slug>.md` in Arabic for any user-visible change.
- ADRs: supersede, never edit; plan files and PRs cite ADR numbers.
- Docs index updated in the same PR (`docs/README.md`, `adr/README.md`).
