# apps/api

- NestJS 12, ESM. `src/main.ts` parses `--role api|worker|migrate|bootstrap` (`src/role.ts`; `migrate` runs `src/migrate/run.ts`; `bootstrap` runs `src/bootstrap.ts`, the first super admin's invitation, documented in `apps/api/README.md`, exit 0 created / 1 refused / 64 usage) and boots through `@eeasy-logistics/config` `loadConfig()`; exit 78 on config error.
- Contexts: `src/modules/kernel|delivery|wms/`, each with `<ctx>.module.ts` and `public/index.ts` (the only cross-context import surface). Kernel imports no context.
- `src/health/` → `/health` (no dependencies) and `/ready` (`AppModule.forRoot(config)` only: elx_app role check, schema version at or beyond the build's, Redis PING, S3 HeadBucket; cached 2 s).

- Migrations (CHORE-3, data §11.9): new files are timestamp-named (`drizzle.config.ts` `migrations.prefix: 'timestamp'`, `YYYYMMDDHHmmss_<slug>.sql` + `meta/<stamp>_snapshot.json`); `0000`–`0015` keep index names. Drizzle's `migrate()` (drizzle-orm 0.45 `pg-core/dialect.js`) applies only entries newer than the last applied row and never re-checks hashes, so `packages/db/migrate` no longer calls it: `checkHistory` (exported) refuses an edited/removed applied file and duplicate journal `when`s and returns the unapplied entries in journal order (`older` when at or before the last applied); `applyMigrations` runs them in one transaction with Drizzle's bookkeeping (`drizzle.__drizzle_migrations` hash = SHA-256 of the file, `created_at` = journal `when`). Never rename a migration to dodge a number. Parallel merge: keep both journal entries ordered by `when`, renumber `idx`; drizzle-kit 0.31 refuses to generate while two snapshots share a `prevId` ("… which is a collision"): the second order points its first snapshot's `prevId` at main's newest snapshot `id`, generates once, deletes a migration that only repeats main's schema and its journal entry, keeps that snapshot. Tests planting migrations copy the folder to a temp dir (`migrate.test.ts` CHORE-3 block) and put the database back afterwards.
