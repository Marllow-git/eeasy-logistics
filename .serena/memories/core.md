# eeasy-logistics · core

Standalone last-mile delivery + WMS for merchants with own drivers and stock. pnpm + Turborepo monorepo. Phase: wave 0 foundation (code exists since PLAT-1, 2026-10-31).

## Invariants (AGENTS.md hard rules, enforced where stated)
- Every operational row has `account_id`; account from token/request context, never a parameter.
- Ledgers (stock, cash custody, driver liability) append-only; writes only through ledger services.
- External side effects only via outbox (ADR-0024); driver location pings exempt (ADR-0028). The only writer is the kernel `OutboxWriter` in the caller's unit of work (PLAT-8); the envelope is immutable by trigger (schema test `envelopeImmutableTables`); Redis holds job ids only; the queue worker writes each row's outcome before its job ends, and adapters report provider failures as `ProviderFailure` (`rate_limited`, `unauthorised`, `permanent`, `transient`).
- No `process.env` outside `packages/config` — enforced by shared ESLint `no-restricted-*` rules and dependency-cruiser `environmentRules()` in every workspace's `test:architecture`.
- Database (PLAT-5): only `packages/db` imports `postgres`/`drizzle-orm/postgres-js` (depcruise `database-driver-only-in-packages-db`); `/platform` only from `modules/kernel/platform/`, `src/worker/system/`, `src/seed/`; `/testing` never in `src/`; `/admin` only `src/seed/`; ESLint forbids the strings `set_config`/`elx.account_id` outside `packages/db/src` and `.tx` on a unit of work outside `*.repository.ts` (and the type no longer has `tx`); schema test `apps/api/test/schema/tenancy.test.ts` enforces `account_id`, policies, append-only triggers (`nullableAccountTables` in `exemptions.ts` for data §2.4 nullable-account tables).
- Web and driver reach the API only through `@eeasy-logistics/contracts`; dependency-cruiser limits `apps/web` to `/staff`, `/recipient`, `/http`, `/unions` (never `/platform`: that is the admin app, ADR-0038; no `/mocks` in src), `apps/admin` to `/platform`, `/http`, `/unions` (rule `admin-contracts-surfaces`; `/platform/mocks` from `tests/` only, rule `admin-contracts-mocks-in-tests-only`; `apps/web` never imports `apps/admin`, rule `web-no-admin-code-or-catalogue`) and `apps/driver` to `/driver`, `/http`, `/unions` (plus `/driver/mocks` from test files only, rule `driver-contracts-mocks-in-tests-only`). Generated code under `packages/contracts/generated/` is never committed.
- Audit log (PLAT-7): `core_audit_log` is append-only and monthly-partitioned; runtime roles have no grant on any partition (schema test); writes through `AUDIT_SINK` only, redacted first; every cross-tenant attempt leaves one committed row. The elx_owner URL is read in `src/` only by the migration job (which also maintains the audit partitions; OPS-1 runs it daily) and the seed tool (ESLint owner-url rule; depcruise `db-migrate-only-in-owner-jobs`); api and worker refuse it in staging and production.
- Request frame (PLAT-6): JSON bodies only, case-sensitive strict routing, the surface from the matched route template; every API route is authenticated unless `@Public()`; the account comes only from the token (surface cookie or bearer), never path/query/body; platform staff reach tenant rows only through `@CrossTenant()` (reason header, audit event); every error is the contract `Error` schema via the global filter.
- Bounded contexts `kernel`, `delivery`, `wms`: kernel imports no context; a context imports another only via `modules/<ctx>/public/` — dependency-cruiser in `apps/api`.
- API types come only from `@eeasy-logistics/contracts` (doc 3 §9, roadmap A-17): no hand-written DTOs, no `class-validator`/`class-transformer`/`nestjs-zod`/`@nestjs/swagger`; strict generated Zod schemas parse every controller input through the kernel `ContractPipe` (PLAT-6); contract types only in `*.controller.ts` and `*.presenter.ts`; services, repositories and Drizzle keep their own types. Enforced by `apps/api/.dependency-cruiser.cjs` rules `no-validation-libraries`, `no-dto-files`, `contracts-only-in-controllers-and-presenters` (violation fixtures in `apps/api/test/architecture/violations/`, asserted by `test/architecture-violations.test.ts`).
- Every string in `ar` and `en`; Arabic default and RTL (ADR-0016). Gregorian dates, Western digits: format only through `@eeasy-logistics/i18n` `format.ts` (no date library); the census fails on Arabic-Indic digits.
- Logical CSS only: ESLint `eeasy/no-physical-direction-utilities` (`packages/config-eslint/rules/`, exported as `logicalCss`, on in `packages/ui`, `apps/web`, `apps/admin`) reports `ml-`/`mr-`/`pl-`/`pr-`/`left-`/`right-`/`text-left`/`rounded-l-`/`border-r-`/`float-left` and the like in `className`/`class` and `cn(`/`clsx(`/`cva(`/`tv(` (object keys count under `cn`/`clsx`, not under `cva`/`tv` variants), with the logical replacement; fixtures in `packages/config-eslint/test/fixtures/`.
- Authorization (PLAT-10): the kernel `PermissionGuard` (after `TenancyGuard`) requires the operation's `x-permission`, read only from the frozen generated `operationSchemas` entry the handler binds; a route on a surface without one (a `@Public()` route: without a door operation; a `@CrossTenant()` mismatch with `x-cross-tenant`; a copy lacking the generated brand) refuses boot (`OperationRoutesCheck`); the guard runs last of the guards; site-scoped requests carry `siteIds` on `RequestContext` (packages/db); ESLint forbids hand-built `@Operation()` arguments in controllers (fixture `test/architecture/violations/lint/forged-operation.controller.ts`). Bundles: `docs/contracts/roles.yaml` (redocly rule `eeasy/role-permissions-in-catalogue`; README §11 parity test in `packages/contracts/test/roles.test.ts`) = seed of `core_roles` (migration 0008, runtime SELECT only; `apps/api/test/roles-seed.test.ts`). `403 forbidden` carries no detail; another site is `404`.
- Authentication (PLAT-11): passwords Argon2id (built-in `crypto.argon2`), every one-time token stored as its SHA-256, TOTP secrets and kept refresh successors and mail links encrypted with the credentials cipher under `<table>:<row id>`; identity tables only on the platform pool; the account of a session only from `selectAccount`/`switchAccount` (a pinned membership); every auth door refusal of an unknown/disabled user has one body and one password verification; the first super admin only through `--role bootstrap`.
- Telemetry (PLAT-14): no span attribute, log line, metric label or Sentry event carries a phone, email, token, code, header or body: span attributes pass an allowlist at export (`AllowlistSpanProcessor`), every string through `telemetry/redact.ts`; metric labels through `safeLabel`; Sentry `beforeSend` = `scrubEvent`, the API reports 500s only. The migrate role loads no SDK (depcruise `migrate-job-loads-no-application` covers `@opentelemetry`/`@sentry`; `main-loads-telemetry-lazily` forbids static telemetry imports in `main.ts`). Telemetry is best-effort: nothing awaits an export in a request. Web and admin (PLAT-14 leg 2): Sentry and PostHog only through their own `/monitoring` and `/ingest/*` routes (CSP stays `'self'`), every event through `@eeasy-logistics/ui/observability` (`scrubSentryEvent`, `scrubAnalyticsEvent`; `/monitoring` re-scrubs and forwards only the configured DSN's events); product events only from the typed catalogue `src/analytics.ts` (`IdsAndEnumsOnly`: ids, enums, numbers, booleans; a free-text string fails typecheck).
- New modules behind rollout mode, default allowlist (ADR-0006). Enforced since PLAT-13: a module's routes carry `@Feature('<key>')` (kernel public), the global `FeatureGate` after the permission guard answers `403 feature_not_enabled` unless K-6 holds (mode `all`, or `allowlist` with the account's flag enabled by a platform user); keys in `apps/api/src/modules/kernel/features/feature-keys.ts` with a seeded `core_rollout_modes` row; accounts exist only through `platformProvisionAccount` (K-1) and turn `active` on the owner's first acceptance.
- Never commit to `main`; one order → one PR; plan file first commit on `feat/<ID>-<slug>`.
