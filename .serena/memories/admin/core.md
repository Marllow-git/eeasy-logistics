# apps/admin

- Platform console (ADR-0038, WEB-19): Next.js 16.4 App Router, same pins, tsconfig, ESLint and `turbo.json` (`^build`) as `apps/web`. Own standalone image (`apps/admin/Dockerfile`, port 3000 in the image) and hostname (`PUBLIC_ADMIN_URL`, local `http://localhost:3002`).
- Route groups `src/app/(auth)` (`/sign-in`, `/sign-in/totp`) and `(platform)` at `/` (no `/platform` segment); each its own root layout in the shared shell (WEB-1 leg 2), same shape as `apps/web` (`mem:web/core`): `(platform)` passes `AppShell` an `account` block (the console name until WEB-2) and placeholder navigation groups (accounts, operations, staff and audit; links to future paths answer 404 until their orders); `(auth)` top bar only. Tailwind via `postcss.config.mjs`; `next.config.ts` = web's (next-intl plugin, `transpilePackages` incl. `ui`, nosniff header).
- Strings: the `platform` namespace lives only here, `messages/{ar,en}/platform.json` (ADR-0038), never in `packages/i18n`. `src/i18n/messages.ts` exports `appMessages` and augments `AppMessages` of `@eeasy-logistics/ui/intl` (typed keys); `src/i18n/request.ts` is `shellRequestConfig(appMessages)`. Since WEB-4 the `(platform)` layout wraps its tree in a second `NextIntlClientProvider` with the shared namespaces plus `appMessages[locale]` (the console screens are client components); `(auth)` still gets no `platform` strings. Parity: `packages/i18n` `test/parity.test.ts` covers this root too.
- Census (WEB-1 leg 2, WEB-2 leg 2): `tests/census.config.ts` + `tests/census/helpers.ts` are copies of web's (base URL `http://localhost:3002` since WEB-2: the API's marker wants `PUBLIC_ADMIN_URL`'s exact Origin), specs `census-shell` (`/`, `/sign-in` + locale switch), `census-errors`, `census-analytics`, `census-auth` (60 tests over `ar`, `ar-390`, `en`); baselines `tests/census/__screenshots__/<project>/<name>-<platform>.png`. Scripts `test:census`, `check:budget` (runs `../web/scripts/check-budget.ts`).
- Config: public values via `@eeasy-logistics/config/web` (`publicConfig()`, same `NEXT_PUBLIC_*` set as web). Contracts: `/platform`, `/http`, `/unions` only (`admin-contracts-surfaces`); `/platform/mocks` from `tests/` only (`admin-contracts-mocks-in-tests-only`).
- Ports: dev/start 3002; CI lane `admin-build-census` (API 3000, admin 3002; build → `check:budget` → census); `main.yml` image `ghcr.io/marllow-git/eeasy-logistics/admin`, probed with `GET /`.
- WEB-4 leg 1: `src/routes.ts` (manifest `consoleRoutes`, `navigationFor`, `homeAreas`; `node --test` via `test:unit`), `src/server/authorization.ts` (`requirePermission(path)` → `forbidden()` under `experimental.authInterrupts`, page `(platform)/forbidden.tsx`), WEB-3's `QueryProvider` in the `(platform)` layout; home = area cards + the `platformListConsumers` block (answers without the API's queues since leg 2, `parked` 0; the census masks its content). `src/support/`: `reason-store.ts` (the tab's support reason in `sessionStorage` `elx:support:<userId>:<accountId>` since the fix round; a reason with non-Latin-1 text or a `%` travels percent-encoded in `X-Support-Reason` (fetch headers take Latin-1 only; the API decodes); the 200 bound counts the decoded text), `support-reason.tsx` (`SupportReasonJanitor` in the layout drops every reason but the user's for the account the tab is on, and all of them through `useSessionEndCleanup` on any session end; `SupportReasonProvider`/`useSupportReason` per account route). `src/accounts/` (list, provisioning form, `account-frame.tsx` = gate dialog + banner + header + tabs; details, invite owner, lifecycle, flags as `next/dynamic` chunks), `src/rollout/`. Census `census-console.spec.ts`: console users `accounts`, `lifecycle`, `rollout`, `outbox`, `staff` (super admins), `operator` (admin), `support`, `colleague`, `relink` (support), `hire` (invited); `consoleAccount(kind, project)` mirrors the seed's active, suspended and provisioned accounts; `acceptOwnerInvitation` posts to `CENSUS_API_URL`.
- WEB-4 traps: a module-level variable is not shared between two route chunks (the provisioning notice lives in `sessionStorage`); `ConfirmDialog` calls `onOpenChange(false)` after a confirm too; before axe wait for CSS transitions and the re-streamed `<title>`; scroll to the top before a full-page capture (sticky banner).
- WEB-4 leg 2: account tabs Members (`accounts/members-tab.tsx`) and Audit (`accounts/audit-tab.tsx`), gated per page by `requireGrant('platform.tenants.read')`; `src/audit/` (`audit-table.tsx` with scopes `account` and `platform`, `audit-values.ts` the disclosure, `/audit` page); `src/outbox/` (`/outbox` list, `outbox-drawer.tsx` on ui `Sheet` + `CodeBlock`, replay and bulk replay behind `ReasonDialog`); `src/staff/` (`/staff`, per-row action menu, invite, role, revoke, TOTP reset); `src/auth/relink-form.tsx` at `(auth)/totp/enrol/[token]` (`platformRedeemEnrolmentLink` → `/sign-in/totp` enrolment; `/totp` is an auth path in `proxy.ts`); `src/lists/` (`list-dates.ts`, `account-filter.tsx`); `src/support/list-reasons.tsx` (the outbox and audit reasons per account, or `platform` for the unfiltered lists, in tab memory). The `(platform)` client provider also carries `settings.roles|members|audit` from packages/i18n (audit action labels are shared there).
- WEB-4 leg 2 traps: a manifest route without its page leaves Next's link prefetch pending forever (Playwright `networkidle` never comes); the contract requires `X-Support-Reason` on `platformListOutbox`/`platformListAudit` even without `account_id` (400 otherwise); the census API has no queues, so replays are asserted and answered by `page.route`; the main navigation's "Audit log" and the account tab share a name (scope by the `account.tabs.label` navigation); growing lists are captured in the viewport with `tbody` masked, dialogs as element screenshots; an `aria-label` must contain the button's visible text (axe `label-content-name-mismatch`, Arabic included).

- WEB-2 leg 1: `src/proxy.ts` (platform cookies `el_platform_at`/`_rt`, `adminGroupOf`: `/sign-in*`, `/signed-out`, `/invitations/*` auth, the rest session), `next.config.ts` rewrites only `/v1/platform/*`, `src/server/api.ts` (`platformServerFetcher`), `/monitoring/csp`.
- WEB-2 leg 2: `src/server/session.ts` (`getPlatformSession`, React `cache()`: no cookie → `/sign-in?next=` without an API call, 401 → `reason=ended`), `(platform)/layout.tsx` renders `src/session/platform-session.tsx` (`SessionProvider surface="platform"`, re-sign-in = `platformLogin` then `platformVerifyTotp`, `codeDescription` the TOTP line) and `UserMenu`. Doors in `(auth)`: `/sign-in` (no reset link; `reason=ended` adds the 12 h idle line), `/sign-in/totp` (`src/auth/totp-door.tsx`: renders only after hydration from the `sessionStorage` step of `src/auth/steps.ts`; code entry or the enrolment view: `platformEnrolTotp` once per view (ref guard), `QrCode` + `ManualKey`, `platformConfirmTotp`), `/invitations/[token]` (`platformAcceptInvitation` → the TOTP step), `/signed-out`. Census-only `(platform)/census-session`. Analytics `auth.sign_in.started|succeeded` (`surface: 'platform'`, `enrolled`), `auth.session.ended`.
- Census stack (WEB-2 leg 2): same as web's (`mem:web/core`): the API without `REDIS_URL`, a worker, Mailpit, `seed:census` before EVERY run (it resets TOTP and `totp_last_step`, re-sends the platform invitation; a second run without it fails the enrolment and invitation checks). `tests/census/session.ts`: `platformSignIn(page, role, project)` (password then the TOTP code over the rewrite), `totpCode` (RFC 6238, a copy of the API's `totp.ts`), `wrongCode`, `mailedLink`. Trap: the API accepts each TOTP step once per user (replay guard, ±1 step), so each census check has its own seeded user (`census-platform-<role>-<project>@census.test`) and `platformSignIn` tries steps −1, 0, +1 then waits for the next step. Clearing cookies in a test must keep `el_locale` (`clearCookies({ name: /^el_platform_/ })`), or the `en` project falls back to Arabic.
