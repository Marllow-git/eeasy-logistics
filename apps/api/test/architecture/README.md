# Architecture test fixtures

`pnpm --filter api test:architecture` runs dependency-cruiser (`apps/api/.dependency-cruiser.cjs`) over `src/` and `fixture/`. `fixture/modules/` mirrors `src/modules/` with permitted imports only, so the rules are exercised on every run. To see a rule fail, add a file under `fixture/modules/<context>/` that imports another context outside its `public/` folder, or a kernel file that imports any context; then delete it.

Environment reads (PLAT-4): the rules in `dependency-cruiser.shared.cjs` at the repository root run in every workspace's `test:architecture`. `no-environment-outside-config` forbids importing the `process` module anywhere; `only-public-config-entry` limits web and driver to their public config entry. A global `process.env` read is not an import, so the shared ESLint rules in `packages/config-eslint` catch it in `pnpm lint` for every workspace. They forbid `process.env`, any `process` member other than `argv`, `stdout`, `stderr`, `exit`, `execPath` and `cwd`, aliasing or passing `process`, and `require` or `import()` of the module. To see both fail, add a file under `src/` with `process.env.X` (lint) or `import { env } from 'node:process'` (this test and lint); then delete it.

Database entries (PLAT-5, ADR-0031): `platform-pool-only-in-platform-code` allows `@eeasy-logistics/db/platform` (the `elx_platform` pool and `PlatformRepository.unscoped()`) only from `modules/kernel/platform/` (the fixture `fixture/modules/kernel/platform/` shows the permitted import) and `src/worker/system/`; `db-testing-only-in-tests` keeps `@eeasy-logistics/db/testing` out of `src/`. To see both fail, add a file under `src/modules/delivery/` that imports either entry; then delete it.

API types from the contracts (PLAT-6 item I, roadmap A-17, doc 3 §9 "Enforcement"): `no-validation-libraries` forbids `class-validator`, `class-transformer`, `nestjs-zod` and `@nestjs/swagger`; `no-dto-files` forbids any `*.dto.ts` file (importing, imported or alone); `contracts-only-in-controllers-and-presenters` allows `@eeasy-logistics/contracts/*` only from `*.controller.ts` and `*.presenter.ts` (the fixture `fixture/modules/kernel/contract/` shows both permitted imports). Their violation fixtures live in `violations/` (a `*.dto.ts`, a `class-validator` import, a contracts import from a service), outside the main run; `test/architecture-violations.test.ts` cruises that folder in the unit suite and fails unless each rule reports its fixture. To see them in the main run: `node_modules/.bin/depcruise src test/architecture/fixture test/architecture/violations --config .dependency-cruiser.cjs`.
