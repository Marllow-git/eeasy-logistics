## 0. Goal

The OpenAPI files in `docs/contracts/openapi/` become the one typed seam between the API, the web app and the driver app: the repository lint rules of document 3 §9 run in CI, each surface is bundled to one file, and from the bundles come TypeScript types, a fetch client, TanStack Query hooks, Zod schemas and MSW handlers per surface, plus the `Permission`, `StreamEventName` and `ErrorCode` unions, so a misspelt permission, event or code fails typecheck; a contract-test harness exercises the generated client against the running API and fails on any undocumented status, field or error code.

## 1. Binding rules and ADRs

- `docs/contracts/README.md` §9 "OpenAPI files and validation" (lint rules, bundle per surface, generated types and clients for `apps/web` and `apps/driver`, contract tests in Compose, YAML is the source of truth, generated code never edited), §1 "Surfaces and base paths", §3 "Conventions" (`Idempotency-Key`, `If-Match`, `X-EL-Client`), §4 "Error model" and `docs/contracts/errors.md` (the `ErrorCode` set), §6 "Server-sent events" (the `StreamEventName` set), §11 "Permission catalogue" (the `Permission` set).
- `docs/architecture/web.md` §2.2 "Boundaries" (the web app reaches the API only through the generated clients; the dependency-cruiser rule exists since PLAT-1) and §2.3 "Code generation" (Orval per surface: fetch client, TanStack Query hooks, Zod schemas, MSW handlers; the three unions; TanStack Query as the cache).
- `docs/architecture/driver-app.md` §1 "Shape" (the driver app shares `packages/contracts` types and client; React Native runtime, no Node APIs in the client).
- `docs/handbook/03-testing.md` table row "Contract" (`packages/contracts/test/`, runs in CI) and "Rules".
- ADR-0003 (one monorepo, contracts as the seam), ADR-0026 (staff surface split by bounded context), ADR-0029 (cursor pagination and SSE event names), ADR-0032 (browser reaches the API on the web origin: same-origin base URL in the browser client, `API_INTERNAL_URL` on the server).
- PLAT-4: any base URL or environment value comes through `packages/config` (`publicConfig()` for web and driver); the generated client takes a base URL and a fetch as parameters and reads no environment.
- Owner decision pending (raised 2026-11-01): a separate admin console application on its own hostname. The per-surface entry points of item E serve both outcomes; nothing here presumes one web app.

### 8.2 Interpretations the lead should check

1. **Repository rules as a Redocly plugin** (`packages/contracts/redocly/plugin.js`, loaded from `docs/contracts/redocly.yaml`): `eeasy/idempotency-key` (resolves `$ref` parameters, operation and path level), `eeasy/permission-in-catalogue`, `eeasy/x-wave-range`, `eeasy/sse-events`; `x-cross-tenant` is a configurable rule switched off for the platform API only. Configurable rules cannot check a resolved parameter list, and the `enum` assertion refuses numbers.
2. **Exempt list** (30 operationIds) is exactly README §3: every `/auth/` door on staff, driver and platform, `driverPostLocations`, `driverVerifyCashPin`, `checkCoverage`, `publicCheckCoverage`, `publicBatchLabels`. No exempt entry was needed beyond that, and no write was missing its key. The 22 outbound `webhooks:` entries of `public.yaml` are skipped by the rule (they are the API's own calls), not listed.
3. **Contract fix forced by the staff join (item B):** two tag names collided across the staff files with different meanings; `staff-delivery.yaml` `locations` (driver positions) is now `driver-locations` and `staff-wms.yaml` `channels` (publications) is now `channel-publications`. Tags only; no path, operationId or schema changed.
4. **`x-sse-events`** values copy each stream operation's own description, which already lists `stream.resync` for the dispatch, driver and recipient streams and not for the import job. The `StreamEventName` test compares with the README §6 "Event names" column plus `stream.resync` (README §6 rules).
5. **Wildcard events:** `delivery.order.*` becomes the type `` `delivery.order.${string}` ``, so handlers for real event types typecheck; a typo inside that family is not caught until the domain event catalogue is expanded (out of scope per 2.5).
6. **Fetcher per call, not module state:** Orval imports `apiFetch`; the caller passes `{ fetcher: createFetcher(...) }` on every generated call (`{ request: { fetcher } }` for hooks). Server components get their own fetcher per request, so no cookie is shared across requests. A call without a fetcher rejects with a clear message (runtime, not type: Orval makes the options argument optional).
7. **Base path in generated URLs:** `getBaseUrlFromSpecification` puts `/v1/<surface>` into every path, so `baseUrl` is the origin (or `''` same-origin). MSW handlers match `*/<path>`.
8. **Fetcher options beyond 2.4:** `webClient` (default true; the driver app sends no `X-EL-Client: web`) and `requestId` (React Native has no `crypto.randomUUID`). `locale` and `headers` accept functions for per-call values.
9. **`ApiError.code`** is `ErrorCode | 'unexpected_response'`: the extra value covers a non-`Error` body (an HTML 502 from the edge). `requestId` falls back to the response header.
10. **MSW as separate entry points** `./staff/mocks`, `./platform/mocks`, `./public/mocks` rather than a `mocks` member of the surface barrel, so importing `./staff` in production never reaches msw or faker; the web architecture rule keeps `/mocks` out of `src`. `@tanstack/react-query`, `msw` and `@faker-js/faker` are optional peer dependencies; `zod` is a dependency.
11. **`apps/web/Dockerfile`** (outside the listed paths): the build step is now `pnpm --filter "@eeasy-logistics/web..." run build`, because the type import makes `next build` (which typechecks) need `generated/unions.ts`; without it the `main.yml` image build would fail. Simulated without Docker (§8.0 E); not run in Docker.
12. **Bundles are linted with Redocly's recommended rules** (`lint:bundles`); the repository rules run on the sources, where per-surface overrides apply.
