## 0. Goal

An owner or admin opens the merchant home and sees the modules visible to the account, changes the account settings in a sectioned form, invites, edits, revokes and resets members from a table with filters, manages sites with their bilingual names, address, National Address short code, point and opening hours, and reads the audit log with filters and cursor paging; every control is gated by the session's permissions and every list, form and dialog works in Arabic and English with the census proving it against the real API, so that the wave 0 exit criterion of an owner creating a site and inviting a staff user runs in the browser and WEB-5 and WEB-6 inherit a `DataTable`, a `Form` and a `Can` that already enforce the web document's rules.

## 5. Exit criteria

- The wave 0 exit path runs in the browser census: the owner signs in, creates a site, invites a staff user who accepts the mail and signs in, in `ar` and in `en`.
- Every control is gated by `me.permissions` and the API's refusals are shown with the catalogue's messages; a viewer never sees a write control and never triggers a write.
- Lists page by cursor with no totals; filters live in the URL; a PATCH sends only changed fields; every write carries one `Idempotency-Key` per intent.
- `DataTable`, `Form` and `Can` are exported from `packages/ui` with two-direction tests for WEB-5 and WEB-6 to reuse.
- Budgets hold; the Arabic release note exists.
