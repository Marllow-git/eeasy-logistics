## 0. Goal

A Delivery consumer writes one `push` outbox row for a driver's devices and the worker delivers it through the Expo push service in batches, with localised title and body rendered on the server from a catalogue, payloads that carry ids only, tickets kept and receipts checked 15 minutes later so a device that unregistered stops receiving pushes through a hook DEL-4 registers, and a recorder stub that local and CI assert on, so that DRV-5 and the DEL orders only produce rows (ADR-0024, integrations §2.5, driver app §8.2).

## 5. Exit criteria

- A `push` outbox row reaches the recorder (local, CI) or Expo (staging) with title and body in the row's locale and a payload of ids only; a second delivery of the same row is a no-op for the app (`push_id`).
- A `DeviceNotRegistered` ticket or receipt reaches the invalidation registry exactly once per device; no token, title or body appears in any log, span or audit row.
- Rate limits reschedule without consuming an attempt; a malformed row is dead at once; receipts are checked after 15 minutes and tickets purged after 7 days.
- Production refuses to start without an explicit push decision.

## 6. Not in this order

### 8.2 Notes

1. **Push refusal binds the worker only** (2.6): staging and production refuse a worker without `PUSH_PROVIDER=expo` and `EXPO_ACCESS_TOKEN`, unless `PUSH_DISABLED=true`; the api never builds a push sender, so it is not asked for an Expo token (least privilege). `PUSH_PROVIDER=stub` is refused in production for every role through `adapterSelectors`. `EXPO_PUSH_URL` other than `https://exp.host` is refused in production only; staging may point at a recorder.
2. **Migration number: 0015** (was 0014). Generated as 0014, the next after `origin/main`'s 0013 at generation and again at first push (2026-11-02). PLAT-12 (PR #89) merged first with `0014_core_accounts_sites` (§9 ruling), so the branch was rebased onto `a16fefa` and the migration regenerated, not renamed (the runner refuses a back-dated file): the old file, snapshot and journal entry removed, `drizzle-kit generate --name=core_push_tickets` run on top of PLAT-12's 0014 snapshot, and the hand-written parts ported to `0015_core_push_tickets.sql`: the `-- reviewed` header, `REVOKE INSERT, UPDATE, DELETE … FROM elx_app`, and the `tenant_isolation` and `platform_access` policies. The generated part is byte-identical to the old 0014.
3. **Template parameters** (2.7): `expires_in_min` is a `count` (`^(0|[1-9][0-9]{0,5})$`, rendered with `formatNumber`); `order_number` is a `reference` (`^[A-Za-z0-9][A-Za-z0-9-]{0,31}$`), passed through unchanged because data §1.3 says the API renders human numbers as `D-000123`, which `formatNumber` would not produce. Both are also capped at 80 characters, one line. The Arabic offer body avoids the minute plural: «الدقائق المتبقية للقبول: {expires_in_min}».
4. **Invalidation failures** (2.5): a handler that throws is logged with its error name and does not fail the row or the receipts run: the push already happened, and the next `DeviceNotRegistered` asks again. The handler writes the tickets before calling the registry, and the receipts job marks the tickets before calling it, so a retry or a second run never reaches the registry twice for one ticket.
5. **`no_device`**: also used when two device rows share a token and dedupe leaves none (cannot happen with a non-empty list; noted for completeness). Two device rows with one token get one push.
6. **`outbox-workers.test.ts`** now uses `webhook` as its test-only kind: `push` has a real handler, and `push-delivery.test.ts` runs `relayBatch` with `push` registered, which would take that suite's pending rows. No assertion changed.
7. **Rate-limited row state** (2.10 says "pending"): every PLAT-8 retry keeps the row `enqueued` with its BullMQ job delayed to `next_attempt_at`; the test asserts `enqueued`, `attempts` 0, `deferrals` 1, `next_attempt_at` at least `Retry-After` ahead.
8. **Offers carry `expires_at`** (§4.1 "expired offers are dropped"): the schema refuses an offer row without it, and any row with it gets `ttl` capped at the time left, so Expo stops retrying an expired offer too.
9. **Purge audit**: one `core.push_tickets.purged` row (`after: { deleted, retention_days: 7 }`, account NULL) per run that deleted tickets; a run every 5 minutes with nothing to delete writes none (288 empty rows a day otherwise).
